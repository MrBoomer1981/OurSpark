# Photochki — фото дня на двоих

Telegram-бот для пары. Утром присылает тему, днём каждый отправляет фото, вечером бот устраивает обмен. Правила и устройство — в [PLAN.md](PLAN.md).

## Запуск на Railway

1. **Бот.** В [@BotFather](https://t.me/BotFather): `/newbot` → имя и username → сохрани токен.
2. **GitHub.** Создай приватный репозиторий и запушь туда проект.
3. **Railway.** New Project → Deploy from GitHub repo → выбери репозиторий. Railway сам находит `Dockerfile` в корне и собирает по нему. Отдельный конфиг Railway не нужен: при падении бот перезапускается по умолчанию, до 10 раз.
4. **Volume.** Добавь к сервису Volume с путём монтирования `/app/data`, там живёт база. Без Volume бот не запустится и напишет об этом в логах: это защита, чтобы деплой не стёр фото и историю.
5. **Переменные** (Variables сервиса):
   - `BOT_TOKEN` — токен из шага 1;
   - `DEBUG=true` — на время проверки включает `/dev`;
   - `TIMEZONE` — если вы не в Москве (например, `Asia/Yekaterinburg`).
6. **Приглашение.** После деплоя открой логи сервиса (или `railway logs`) и найди строку «Ссылка-приглашение». Открой ссылку сам — бот пришлёт её же в чат, перешли её второму участнику.
7. **Проверка.** Пройдите вдвоём чек-лист из раздела 7 [PLAN.md](PLAN.md): `/dev` запускает тему, напоминание и обмен, не дожидаясь расписания.
8. **Боевой режим.** В `/dev` нажми «Очистить историю», затем поставь `DEBUG=false`.

Дальше каждый push в `main` — новый деплой. Деплоить можно когда угодно, даже днём, когда кто-то уже прислал фото: оно не потеряется. Подробности — в разделе «Надёжность при деплое» в [PLAN.md](PLAN.md). После деплоя в логах видна строка «База: … · участников: … · фото за сегодня: …».

## Переменные окружения

| Переменная | По умолчанию | Что это |
|---|---|---|
| `BOT_TOKEN` | — | токен от @BotFather |
| `INVITE_CODE` | генерируется | свой код для ссылки-приглашения: латиница, цифры, `_`, `-`, до 64 символов |
| `TIMEZONE` | `Europe/Moscow` | часовой пояс пары |
| `DEBUG` | `false` | `true` включает `/dev` |
| `DB_PATH` | `data/bot.db` | путь к базе SQLite |

Время темы и обмена меняется в самом боте: `/settings`. Предложить свою тему — `/addtheme`: она попадёт в копилку и выпадет в один из ближайших дней с подписью автора.

## Локальный запуск

Нужен **отдельный тестовый бот**: один токен нельзя слушать из двух мест, иначе прод и локальная копия будут отнимать друг у друга обновления.

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # вписать токен тестового бота
python -m bot
```

## Темы

Темы лежат в двух файлах, одна строка — одна тема в формате `Название — подсказка`:

- `themes/simple.txt` — простые, такие можно снять за минуту там, где ты сейчас. Выпадают в 70% дней.
- `themes/creative.txt` — посложнее, надо подумать или что-то поискать. Выпадают в 30% дней.

Тема, по которой прислали хотя бы одно фото, больше не выпадает. «Другая тема» всегда даёт простую. Дописывать темы можно в любое место файла, но названия не должны повторяться ни в одном из двух файлов. Сколько тем ещё не использовано, показывает `/dev`.

## Новые фишки

Каждая фича — модуль в `bot/features/` с объектом `Feature`: роутер, задачи планировщика, команды меню, свои строки и кнопки в вечерней карточке (`card`), хук `on_exchange`. Подключается одной строкой в `bot/features/__init__.py`. Схема базы меняется только новой миграцией в конце списка `MIGRATIONS` в `bot/db.py`. Подробнее — в [CLAUDE.md](CLAUDE.md).
